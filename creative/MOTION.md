# Motion Language

Captionflow motion should be fast enough for short-form content, but never frantic.

## Character

Think:
- controlled velocity
- strong easing
- crisp spatial logic
- clean object continuity
- purposeful depth
- quick comprehension
- premium restraint

The motion should feel engineered, not randomly generated.

## Default easing language

A useful house curve taken from the product motion language is:

`cubic-bezier(0.16, 1, 0.3, 1)`

Use it often for premium entrances, depth changes and large UI moves. Do not force it onto every micro-interaction.

## Timing

For social motion design:
- the first visual event should happen immediately
- avoid long static intros
- most beats should resolve quickly enough to maintain forward movement
- allow brief holds only when the viewer needs to read or understand a transformation

Fast does not mean constant motion. Contrast motion with short moments of stillness.

## Preferred motion ideas

- object-to-object morphs
- masked reveals driven by existing UI geometry
- split/recombine transitions
- camera push through interface layers
- parallax with restrained depth
- timeline/playhead-driven reveals
- type that becomes interface
- interface that becomes typography
- clip blocks reorganizing into a finished composition
- a single active word triggering the next scene
- zooming from macro product view into a focused control
- precise scale and perspective changes
- controlled blur only during velocity or depth transition

## Depth

Use 3D or pseudo-3D when it clarifies hierarchy.

Good depth stack:
1. atmospheric background
2. main product plane
3. foreground detail or text

Avoid stacking five layers merely to look sophisticated.

## Blur

Blur is transitional, not a permanent aesthetic.

Use it for:
- focus change
- fast entrance/exit
- depth separation
- match transition

Return important elements to crisp focus quickly.

## Springs

Use sparingly. Captionflow should not bounce like a playful mobile app.

If spring behavior is used, it should settle quickly with minimal overshoot.

## Camera

Camera movement should have a reason:
- reveal hierarchy
- redirect attention
- bridge scenes
- create scale contrast

Avoid arbitrary orbiting cameras or continuous 3D rotation.

## Typography animation

Good:
- word-driven reveals
- mask/clip reveals
- controlled tracking or scale interpolation
- single-word emphasis
- type integrated with product UI

Bad:
- every letter flying independently without reason
- constant kinetic text
- trendy effects repeated across every line

## Transitions

Prefer transitions that preserve visual continuity.

Examples:
- active caption highlight expands into a full-screen color field, then contracts into the next control
- playhead becomes a vertical divider in the next scene
- export button becomes the final CTA/button state
- UI panel scales past camera and its edge becomes the next frame's mask

Avoid default crossfades unless the quietness is intentional.

## Motion density

A high-end result usually has fewer, better motions.

At any moment, identify the primary motion. Secondary motion should support it at lower amplitude.

If everything moves, nothing has hierarchy.
